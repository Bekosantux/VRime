# 入力バッファと送信

## 入力バッファ

- バッファは「確定済みの文字列」と「未確定のかな」を持ち、カーソル位置を管理する。キーボードの入力欄に表示する。
- 未確定のかなは確定済みの文字列のカーソル位置に置かれ、未確定の中にもカーソルを持つ。かなの入力は未確定のカーソル位置に挿入する。
- 「←」「→」「消去」と直前の文字の切り替え（子音側のトリガー・「小゛゜」）は、未確定のかながある間は未確定の中だけで動作し（先頭や末尾でも確定済みの文字には作用しない）、未確定が空のときは確定済みの文字列に作用する。
- 「確定」キーの動作:
  - 未確定のかながあれば、変換せずにそのまま確定済みの文字列にする。
  - 未確定のかながなければ、バッファの内容を**送信**する。送信に成功したらバッファを空にする。送れなかったときはバッファを残し、振動で知らせる。

### 文字数

- 文字数は確定済みと未確定の合計で、単位は UTF-16 のコードユニット（絵文字などは2文字分）。状態行の右端に、上限がなければ「N 文字」、上限があれば「N / 上限」と表示する。
- 文字数の上限は送信先で決まる。送信先が VRChat のときだけ144文字で、それ以外は上限なし。
- 上限があるときは、上限を超える入力を受け付けず、振動で知らせる。変換結果の確定で上限を超えるときも確定せず、候補を選び直せる。
- 送信先が途中で VRChat に変わり、入力済みの内容が上限を超えた場合は、内容を切り詰めない。超えている間は文字数を赤で表示し、送信しない（確定キーは無効の振動で知らせる）。消去・移動・未確定の確定など、文字数を増やさない操作はできる。
- 文字数がちょうど上限のときは、上限に達したことを示す色で表示する。

### 通知

- 入力欄の状態行に、送信できなかった理由などを通知する。
- 通知は、入力バッファの内容が変わったとき、またはキーボードを開いたときに消す。送信の成功は通知しない（バッファが空になることで分かる）。成功してバッファを空にしたときは、それまでの通知も消える。

## 送信先

前面のウィンドウを毎フレームの入力の処理の前に調べ、送信先を決める。送信・状態行の送信先の表示・文字数の上限・入力中の文字の表示は、同じ送信先に従う。

| 前面のウィンドウ | 送信 |
|---|---|
| VRChat | OSC でチャットボックスに送る（[VRChat](#vrchat)） |
| それ以外（デスクトップのアプリ） | 文字列をクリップボードに置き、前面のウィンドウに Ctrl+V を送って貼り付ける（[デスクトップのアプリ](#デスクトップのアプリ)） |
| 本アプリ自身（開発中の Unity エディターを含む） | 送信せず、入力欄にその旨を通知する |
| なし | 送信せず、入力欄にその旨を通知する |

- 状態行には「送信先: 名前」と表示する。名前は VRChat なら「VRChat」、デスクトップのアプリならアプリの名前（実行ファイルの説明。なければプロセス名）、本アプリ自身なら「このアプリ」、前面のウィンドウがなければ「なし」。
- 送信できなかったときは、バッファを空にしない。

## デスクトップのアプリ

- 貼り付けで送るため、送り先のアプリの IME の状態に関係なく、文字が確定した状態で届く。文字をキー入力（`KEYEVENTF_UNICODE`）として送ると、送り先の IME がオンのときに未確定の文字として取り込まれ、Chrome では漢字だけが後ろにまとめて入るなど順序も崩れる。
- Ctrl+V で貼り付けられないアプリには届かない。
- 貼り付けた後に Enter は押さない。
- 管理者権限で動いているウィンドウには送れない（Windows の仕様）。送信の後の戻り値では検出できないため、送信の前に対象のプロセスの昇格状態を調べる。昇格している、または昇格状態を調べられない場合は、送信せずに入力欄にその旨を通知する。
- 入力する手順の想定: ダッシュボードのデスクトップ表示で入力欄をクリック → ダッシュボードを閉じる → キーボードで入力して送信。

### クリップボードの扱い

- 貼り付ける前に元の内容を退避し、貼り付けから 1秒後に戻す（送り先が貼り付けを処理し終えるのを待つため）。それまでに利用者や別のアプリがクリップボードを書き換えていれば、戻さない。
- 戻す前に続けて送ったときは、最初に退避した元の内容を戻す。
- 送信した文字列と戻した内容には、クリップボードの履歴・クラウドへの同期・監視アプリに記録させないための形式を加える。
- 戻せるのはメモリの形式（文字列・画像（DIB）・ファイルの一覧など）と拡張メタファイル。それ以外の GDI のハンドルの形式・オーナー描画・アプリ固有のハンドルの形式は戻らない（ビットマップは DIB から Windows が再生成する）。
- 他のアプリがクリップボードを開いたままで開けないときは、送信せずに入力欄にその旨を通知する。戻す時刻に開けないときはフレームごとに再試行し、5秒過ぎても開けなければ戻すのを諦める。
- アプリの終了時に戻す前の内容があれば、時刻を待たずに戻す。

## VRChat

| 項目 | 内容 |
|---|---|
| 宛先 | `127.0.0.1:9000`（UDP） |
| 送信 | `/chatbox/input` 文字列, `true`（VRChat のキーボードを通さず即時表示）, `true`（通知音を鳴らす） |
| 入力中の表示 | 送信先が VRChat で、キーボードを開いていてバッファが空でない間は `/chatbox/typing true`、条件を外れたら（送信先が VRChat でなくなった、空になった、閉じた）`false`。値が変わったときだけ送る |
| 入力中の文字 | 設定がオンで、送信先が VRChat で、キーボードを開いていてバッファが空でない間、表示どおりの文字列（未確定のかなを含む）を `/chatbox/input` 文字列, `true`, `false`（通知音なし）で送る。144文字を超える分は送らない。条件を外れたら空文字列を送って表示を消す（送信でバッファが空になったときは、送信した文字列に置き換わるため送らない）。アプリの終了時も、表示していれば間隔を待たずに消す |
| 文字数 | **最大144文字**（超えた分は VRChat 側で切り捨てられる）。送信先が VRChat の間だけ上限にする |
| 送信間隔 | **1秒以上空ける**（0.3秒間隔では途中のメッセージが抜けた。1秒間隔では全件表示された）。送信と入力中の文字で間隔を共有する。間隔内に次の送信があれば、待ってから順に送る。入力中の文字は送信より後に回し、間隔内の変更は最新のものだけを送る。送信すると、まだ送っていない入力中の文字は取り下げる |

- 送信は、送信間隔を待つキューに入った時点で成功とみなす。
- 文字数は UTF-16 のコードユニットで数える。VRChat 側の数え方は未確認（[ROADMAP.md](../ROADMAP.md#未決事項) の U-9）。
- 起動時に VRChat を前面にする（設定「起動時にVRChatにフォーカス」がオンのとき）。VRChat のウィンドウがなければ（起動していない、または起動の途中）何もしない。Windows が切り替えを許さなかったときは、ログに残して起動を続ける。開発用のキーボードの環境（入力を読むのに本アプリのウィンドウが前面である必要がある）では前面を移さない。
